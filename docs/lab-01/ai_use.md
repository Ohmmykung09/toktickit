# Lab 1 AI Use and Reflection

## AI Tool Used

I used Codex as my AI coding assistant during Lab 1. I used it to help interpret the requirements, plan the GitHub workflow, implement each feature branch, debug errors, improve tests, and prepare documentation evidence.

I did not treat the AI output as automatically correct. I reviewed the suggested code, ran the commands myself, checked errors, asked for explanations when needed, and only used changes that matched the Lab 1 requirements.

## Prompting Reflection

At the beginning of the lab, my prompts were broad because I was still trying to understand the assignment. These prompts were useful for planning, but they were not specific enough for implementation.

As I worked through the lab, I improved my prompts by focusing on one Issue and one branch at a time. For example, I asked for only the project foundation in Issue 1, only the health check in Issue 2, only the category seed in Issue 3, and only the category list in Issue 4. This made each Pull Request easier to review and kept the work aligned with the acceptance criteria.

The most useful prompts included clear constraints from the lab sheet, such as the required framework choices, branch names, REST endpoints, database model, seed data, and test tools. When the reviewer requested changes, I used follow-up prompts that included the exact review comment and asked for a focused fix.

I also learned that AI can produce code that looks correct but still needs verification. For example, I had to run `npm test`, `npm run build`, `npm run db:check`, `npm run prisma:seed`, and manual browser checks to confirm that the implementation actually worked.

Overall, AI helped me move faster and understand errors more clearly, but I still had to make the final decisions, review the code, run the tests, and take responsibility for the submitted work.
