# Lab 3 AI Use and Reflection

## AI Tool Used

I used Codex as a specification and coding assistant during Lab 3. I used separate specification-oriented prompts to turn the stakeholder request into an engineering contract, and implementation-oriented prompts to complete bounded increments with tests. I remained responsible for accepting the contract, checking the changed files, running commands locally, interpreting peer review, and deciding whether the evidence met the Product Definition of Done.

## My Reflection

The most useful AI interactions were constrained by the current branch, the approved contract, and the evidence expected from that increment. Prompts that explicitly named security boundaries, excluded scope, failure behavior, and test obligations produced changes that were easier to review than prompts that merely asked to build a screen.

Peer review exposed assumptions that were not visible in the initial happy paths, especially around concurrent authority changes, database migration safety, lost HTTP responses, and Unicode boundaries. I used the AI coding assistant to explain each concern, locate the relevant ownership boundary, and propose a regression before changing the implementation. I then inspected the diff and ran the isolated quality suite locally.

AI accelerated specification, implementation, and test generation, but it did not replace engineering responsibility. I approved the branch scope, protected secrets, reviewed database and API behavior, decided which reviewer findings were blocking, and kept GitHub publication and merge decisions under human control. The final claim of completion depends on passing evidence from the reviewed integrated tree and a final rerun on `main`.
